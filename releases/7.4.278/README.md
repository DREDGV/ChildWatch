# ChildWatch 7.4.278 — комплект для самостоятельной публикации

Оба APK собраны и подписаны постоянным ключом проекта. ParentMonitor установлен поверх 7.4.276 на папин Samsung SM-S711B (R5CX71CKKJW), данные не очищались. Детский телефон не подключён. Публикацию сервера владелец выполняет самостоятельно; живой сервер на момент проверки отдавал 7.4.277.

## Что передать на сервер

- `server-source-7.4.278.zip` — только пять изменённых файлов: `server/index.js`, `server/routes/location.js`, `server/routes/pickups.js`, `server/services/FamilyHistoryPageStore.js`, `server/services/FamilyPickupService.js`. Пути в архиве начинаются с `server/`; при размещении снять этот префикс и сохранить остальную структуру относительно корня работающего Node-приложения. Контрольные суммы в `server-files.sha256`.
- `ParentMonitor-7.4.278.apk`, `ChildDevice-7.4.278-debug.apk` и `manifest.json` — комплект OTA. Манифест содержит версии, packageName, размеры, SHA256 и сертификат подписи. APK лежат локально в этой папке и не отправляются в Git.

## Порядок

1. Сохранить прежние пять файлов, прежний OTA-манифест и согласованный снимок рабочей SQLite (через SQLite backup, не простым копированием открытой БД). Рабочую БД, настройки, uploads и node_modules комплектом не заменять.
2. Разместить пять JS-файлов, проверить каждый через `node --check`, перезапустить штатную службу. Проверить прежние функции, серверные журналы и работу `/api/pickups` с действующими авторизованными клиентами. Таблица pickup создаётся сервисом; новый npm-пакет не нужен. При ошибке вернуть прежние файлы и перезапустить службу.
3. Загрузить оба новых APK в действующий каталог OTA. Только когда оба файла доступны, заменить `manifest.json` атомарно. Сравнить отдаваемые файлы по размеру/SHA256 с этим манифестом. Не запускать `release-updates.ps1` ради публикации уже готового комплекта: он выбирает новый номер и пересобирает.
4. Обновить детское приложение через OTA поверх прежнего. Проверить ребёнок → просьба → родитель принимает → прибыл → две стороны подтверждают встречу. Отдельно проверить потерю связи, рестарт и разрешение уведомлений.

Изолированная SQLite-проверка `node server/__tests__/family-pickup-release.node.cjs` прошла: один победитель из двух одновременных принятий, повтор UUID, возврат просьбы, подтверждение встречи, истечение после нового экземпляра сервиса и запрет доступа. Семейные полномочия в этой проверке задаются фикстурой: это не доказательство реального endpoint/телефонов.

На папином телефоне сделан снимок карты 278: видны пустое InfoWindow и перекрытие правых нижних кнопок кнопкой «История». Они зарегистрированы в TODO CW-06/278-MAP и не исправлены в этих APK. Сквозная работа новой функции и её активной домашней карточки на установленном телефоне ещё не подтверждена.

Исходники выпуска: коммит `8c567d3`, отправлен в GitHub `DREDGV/ChildWatch`, ветка `feat/family-profiles`. Контрольные суммы APK повторно сверены с манифестом; журнал SQLite: `.runtime/pickup-release-278-check.log`.
