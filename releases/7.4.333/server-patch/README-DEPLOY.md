# Задание серверному агенту: Морской бой для ChildWatch 7.4.333

Владелец поручает обновление сервера отдельному агенту. Этот пакет подготовлен локально; основной агент сервер и OTA не публиковал. Подписанные приложения333 устанавливаются на подключённые телефоны отдельно.

## Состав и совместимость

Скопировать относительно корня действующего сервера ровно три файла из `server/`:

- `services/FamilyGameService.js`
- `services/BattleshipRules.js`
- `routes/family-games.js`

Контрольные суммы/размеры: `verification.json`. Существующая зависимость — `services/DeviceAccessService.js`; её текущий исходный hash приложен как reference, это не требование перезаписать действующий файл вслепую. Проверить методы `isDeviceRevoked`, а у dbManager — `withTransaction`, `getFamilyMembers`, `getFamilyIdentityMembershipsForDevice` и обычные SQL get/all/run. Express/sqlite3 уже используются сервером; новые npm пакеты не нужны.

`reference/index.js` — только пример интеграции, **не файл для замены**: на сервере могут быть более свежие чужие изменения. В действующий index добавить следующие строки, если их ещё нет:

```js
const createFamilyGameRoutes = require("./routes/family-games");
// после создания dbManager/authMiddleware, рядом с остальными защищёнными API:
app.use("/api/family-games", authMiddleware.authenticate(),
  authMiddleware.rateLimit(60_000, 90), createFamilyGameRoutes(dbManager));
```

Не создавать второй mount, не ослаблять авторизацию и не менять VPN. Старый клиент продолжает работать; новый семейный режим включается только при наличии BATTLESHIP в capabilities. Одиночная игра сервера не требует. Транскрибацию не включать.

## Порядок выкладки

1. Сверить реальный каталог сервера/процесс/SQLite, сохранить резервные копии изменяемых файлов и согласованный snapshot базы при остановленных записях. Не использовать копию старой базы как новую рабочую.
2. Сверить исходные зависимости, скопировать три runtime файла, точечно интегрировать маршрут в действующий index. Проверить sha256 файлов по verification.json; `node --check` всех трёх и изменённого index.
3. Перезапустить существующий процесс штатным для этого сервера способом. Проверить логи, `/api/health` и прежние API, целостность SQLite/состав семей и сообщений.
4. `/api/family-games/capabilities` без авторизации должен вернуть401. С разрешённым семейным клиентом — success/protocolVersion1/games включает BATTLESHIP. Проверка401 сама по себе не доказывает рабочую игру.
5. После333 на телефонах: раздел «Игры» → «С участником семьи», приглашение/принятие, оба флота, поочерёдные выстрелы, свои/чужие поля, возврат в партию. Повтор запроса не создаёт новый выстрел; чужие/отозванные участники не получают флот. Не отправлять тестовые приглашения в рабочую семью без команды владельца. Не устраивать обрыв дольше минуты.

База получает только дополнительный family_games.type; существующие комнаты сохраняются. Старый сервис не умеет читать новые Battleship строки, поэтому откат старого кода после создания новых партий требует отдельной проверки, без автоматического возврата старой базы поверх новых данных.

При отдельном поручении опубликовать OTA: брать пару APK и manifest из родительского каталога333, сначала загрузить оба APK и проверить размер/SHA256, затем атомарно заменить manifest; package/cert сохранить. После публикации скачать опубликованный manifest/APK и сравнить hashes. Текущая задача основного агента не включает публикацию OTA.

Полный wire контракт/доказательства: `CONTRACT.md`. Передать владельцу фактический результат выкладки, публичную версию отдельно, журнал и ещё не проверенные телефонные сценарии.
