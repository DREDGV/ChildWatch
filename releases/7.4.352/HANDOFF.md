# ChildWatch 7.4.352 — поручение серверному агенту

Клиентский выпуск: улучшенная галерея, приглашения в игры из разных экранов, новое оформление/управление Змейки. Базовый серверный комплект игр 7.4.348 уже установлен по отчёту владельца. VPN не менять. Рабочие данные и семейные привязки сохранять.

## Серверный delta к 348

Из server-patch/server/ заменить routes/family-games.js и добавить services/FamilyGameInviteDelivery.js. Новых npm-зависимостей, схем/миграций SQLite нет. Остальные игровые службы из 348 сохраняются.

В действующем index.js выполнить ровно три изменения, не заменяя его целиком:

```js
// Рядом с импортом FamilyGameService:
const FamilyGameInviteDelivery = require("./services/FamilyGameInviteDelivery");
// После создания io и существующего familyGameService:
const familyGameInvites = new FamilyGameInviteDelivery(io, familyGameService);
// В существующем mount /api/family-games, сохранив authenticate/rateLimit:
createFamilyGameRoutes(dbManager, familyGameService, {
  notifyChanged: game => familyGameInvites.changed(game)
})
```

reference/index.js — только образец; index-integration.diff показывает delta относительно index из комплекта348. Если действующий index содержит дополнительные изменения, сохранить их и интегрировать эти три точки вручную. Не дублировать mount или создавать второй io/FamilyGameService. Новая служба использует существующий основной io, а не namespace /family-games.

До выкладки определить настоящий cwd/process/SQLite файл через текущую конфигурацию PM2. Сохранить отдельно бэкап затрагиваемого кода и согласованный SQLite backup (онлайн .backup или после остановки процесса), не копировать работающую базу простым cp. Сверить SHA256SUMS.txt внутри server-patch и неизменённые игровые зависимости в verification.json. Применить delta, node --check для двух runtime файлов и действующего index.js. Скопировать только tests/ в __tests__/ и выполнить:

```sh
node --test __tests__/game-invite-delivery.node.cjs __tests__/family-games.node.cjs
```

Тесты работают с изолированными БД. После успешных проверок перезапустить только существующий процесс ChildWatch. Для текущих realtime игр оставить один процесс/PM2 fork, не менять env мониторинга/ASR (ASR остаётся выключенной). Проверить startup log, health, отсутствие ошибок и integrity/счётчики рабочих данных. При ошибке вернуть бэкап кода, не восстанавливать старую БД поверх новых данных автоматически.

## Публикация OTA

После серверной проверки взять ota.zip из этого выпуска. Сначала сверить ARCHIVE-SHA256SUMS.txt, затем распаковать в отдельный временный каталог. В manifest.json оба code2000000352, подпись прежняя, parent ru.example.childwatch, child ru.example.parentwatch.debug. Не публиковать child под другим packageName.

В действующем /var/www/childwatch-updates сохранить старый manifest. Разместить два APK по именам из нового manifest, сверить их размер/SHA256/сертификат. Только после готовности APK атомарно заменить manifest.json (через временный файл и mv внутри того же каталога). Старые versioned APK не удалять и не перезаписывать. При изменившейся структуре OTA свериться с текущими server routes/PM2; структура из архива — два APK и manifest в корне.

Проверить публичный http://31.28.27.96:3000/updates/manifest: versionCode, packageName, sha256 совпадают с локальным manifest. Скачать оба URL /updates/files/<имя>, проверить полный SHA256 и размер. Одного HTTP200 недостаточно. Проверить «Есть обновление» на другом семейном телефоне версии348 без установки downgrade.
