# ChildWatch 7.4.299 — исправление детского окна обновлений

## Причина

На рабочем Moto ZY227XB2QD (Android 11/API30), версия 7.4.293-debug, нажатие «Есть обновление» воспроизводимо завершало приложение: NullPointerException в MainActivity.setupUI:386, LinearLayout.getChildCount(). HomeDetailSheet временно переносит updateNoticeContainer из дерева Activity в BottomSheetDialog; global-layout listener искал контейнер через Activity.findViewById и получал null.

В parentwatch/MainActivity.kt сохранены стабильные ссылки на контейнер и кнопку до переноса. Те же ссылки используются при открытии и переразметке. В родительском приложении уже использовался binding со стабильными ссылками; его поведение не менялось. Скачивание, установщик, подписи, Room и серверный код не менялись.

## Выпуск и устройство

- Оба приложения 2000000299, родитель 7.4.299 / ребёнок 7.4.299-debug, сохранены package IDs и проектная подпись.
- Сборка обоих APK PASS129сек: `.runtime/update-fix-7.4.299-build.log`.
- На Moto child299 установлен поверх293 без удаления: push1сек/install16сек, `.runtime/update-fix-7.4.299-install.log`; firstInstallTime23.09 сохранён. Экран показал Лёву и «Фоновая служба включена», `.runtime/cw-update-after.xml`.
- OTA SHA-256/размер/подписи проверены. Архив `ota-7.4.299.zip`, manifest в ota/, копия в локальном updates/.
- Публичный manifest09.10 подтверждает296 у обоих. OTA guard299>296/package/certificate PASS. SSH ранее timeout; исправленный комплект ещё нужно опубликовать через серверного агента. Серверный код повторно обновлять не нужно.
- Родителю, уже установившему296, обновляться срочно ради этой ошибки не требуется: в299 его функции соответствуют296. Оба APK подготовлены для согласованной OTA-публикации.

## Проверка окна

Адресный HomeUpdateSheetTest запускает настоящий MainActivity на подключённом Moto, добавляет временный элемент уведомления только в UI, открывает существующую панель кнопкой, проверяет отсутствие контейнера в Activity после переноса, вызывает реальные global-layout listeners, закрывает и ждёт asynchronous onDismiss, повторяет3раза. Скачивание, установка, сигналы, запись, настройки, семейные данные не затрагиваются; временный элемент удаляется. Существующие instrumentation fixtures для записи/управления не запускались.

Первый прогон дошёл до открытого окна без прежнего NPE, но преждевременно проверял возврат контейнера до доставки onDismiss. Исправлено ожидание главной очереди в самом тесте. Итог повторного прогона записывается в TODO и `.runtime/update-fix-7.4.299-native-test-final.log`.

Для повторной сборки test APK штатный version policy зарезервировал300; это номер только тестовой сборки. APK300 на рабочий телефон не устанавливался и не выпускался, production OTA-комплект остаётся299.

## Передача агенту публикации

Опубликовать только новый OTA-комплект: APK первыми, manifest атомарно последним, сохранить старый manifest/APK; до замены проверить текущую версию/подпись/package, после — скачать оба публичных APK и сверить hash/size. Данные сервера и его код не заменять. Детские телефоны со старым падающим окном могут потребовать установки исправленного APK поверх существующего приложения; не удалять приложение. После исправленной версии проверить будущий доступный OTA-релиз штатным путём.
