## Публикация агентом с доступом к серверу

Архив `../client-update-7.4.288.zip` содержит два APK, manifest.json, SHA256SUMS.txt, source-snapshot.json, этот README и `publish-updates.sh` — копию уже используемого проектного атомарного publisher. БД/ключей/токенов в комплекте нет.

1. Проверить актуальный `http://31.28.27.96:3000/updates/manifest`: у обоих code должен быть **ниже2000000288**, package/certificate совпадать с новым manifest. При уже опубликованном более новом code остановиться.
2. На сервере определить каталог `CW_UPDATE_DIR` текущего процесса; проектный publisher читает `pm2 env 0`, затем использует `/var/www/childwatch-updates` как fallback. Сохранить действующий manifest с датой в том же каталоге.
3. Распаковать комплект, проверить `sha256sum -c SHA256SUMS.txt`. Создать `/tmp/cw-updates-in`, скопировать туда **два APK и manifest.json**. Прежние APK не удалять.
4. Выполнить приложенный `publish-updates.sh`. Он сериализует финальную проверку номера/пакета/сертификата/байтов, размещает APK сначала, заменяет manifest атомарно последним. Если каталог отличается, убедиться, что `CW_UPDATE_DIR` действительно читается publisher.
5. Прочитать публичный manifest обратно, проверить288 у обоих и скачать оба `/updates/files/<file>`; SHA256/размер должны совпасть с manifest. Только после этого считать OTA опубликованной. На текущих двух телефонах288 уже стоит, переустановка не нужна.

Для следующей сборки номер задавать явно: авторасчёт Git сейчас ниже уже испытанной287. Не выпускать284 и не пересобирать изменённый код под уже использованной288; следующий изменённый клиент должен иметь новый code.
