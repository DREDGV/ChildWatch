# Чат: проверка GIF и разделение меню · 10.10.2026

Владелец сообщил дефект после серверной выкладки308. На Samsung с установленной308 сохранён настоящий экран отправленной GIF: цветной прямоугольник, название файла, размер и кнопка открытия. Приватные снимки находятся в `.runtime/chat-field-2026-10-10/`, в Git не включены. Все текущие статусы и следующий шаг — только в TODO.md.

## Подтверждённые причины

1. Общий `ChatAnimatedMedia.load` использовал `dontAnimate()`. В Glide4 этот вызов отключает декодеры анимированных ресурсов — GIF возвращается статичной. [Официальная документация Glide](https://bumptech.github.io/glide/javadocs/420/index-all.html) описывает именно это поведение. Изолированный тест на Samsung до исправления упал на `GIF decoded as animation`: `.runtime/chat-field-2026-10-10/gif-native.log`.
2. Выбор каталога и черновик использовали `BitmapFactory`/`setImageBitmap`: только первый кадр независимо от включённой настройки.
3. ChatAdapter безусловно показывал filename/size/open для всех вложений. Фон `primary_container` и200×150dp `centerCrop` создавали прямоугольную карточку и обрезали квадратную иллюстрацию.
4. GIF лежали в меню файлов вместе с фото и записью. На обоих клиентах этот вход перемещён в панель со смайлом.

Каталог v1 уже содержит прозрачные GIF256×256,12кадров/100мс, бесконечный цикл. Технический текст не встроен в картинку. Сами анимации — небольшое покачивание/пульсация, а не полноценная анимация персонажа; этот визуальный недостаток не устраняется ремонтом декодера. Опубликованные байты v1 не заменялись. Новые выразительные движения потребуют нового каталога и отдельного создания иллюстраций/кадров.

## Изменения исходников

- Общий декодер сохраняет GIF; настройки отключения, scope владельца, остановка вне видимости и очистка остаются.
- Общая нижняя панель вложений: Фото, Аудио, Документ и отмена. Она не содержит GIF/стикеров. Микрофон запрашивается только после выбора аудио, файл не отправляется до обычной кнопки отправки.
- Панель со смайлом: Смайлы, Стикеры, GIF и импорт GIF с телефона. Стандартная emoji-клавиатура сохранена. Просмотр каталога анимирован, при закрытии/смене вкладки ресурсы освобождаются.
- Черновик анимируется тем же декодером; ограничение GIF размера/кадров/пиксельного бюджета сохранено. Он владеет своим файлом и не удаляет его после декодирования. Scope проверяется после асинхронных операций.
- GIF/стикер в сообщении: квадрат, FIT_CENTER, прозрачная карточка без filename/size/open. Нажатие на картинку открывает прежние действия; имя доступно для accessibility. Состояние отправки и повтор при ошибке сохранены. При повторном использовании holder обычный файл возвращает прежние элементы.
- Исправлена найденная низкая читаемость имени/времени вне исходящей цветной bubble: используется `on_surface_variant` вместо белого.

Ни schema Room, ни серверный protocol/каталог не менялись. Основные APK308 на телефонах пока не заменялись: проверка новых исходников и отдельной native fixture не равна установке исправленного клиента.

## Приёмка

Первый safe compile обоих клиентов и тестового пакета: PASS1м50с. Следующий compile после scope/лимитов и новых fixture-панелей: PASS1м42с. Первый GIF native test до удаления dontAnimate: воспроизводимый FAIL1/1 на статичном drawable. Итог: финальный compile обоих клиентов с picker lifecycle PASS1м31с/66tasks; финальный shared panel/test compile PASS15сек/45tasks. Повтор native2/2 PASS6,294сек, `.runtime/chat-field-2026-10-10/panel-native-final.log`. Снимки новых панелей действительно просмотрены; тестовый пакет удалён, рабочий чат308 возвращён. Первая попытка снимков была перекрыта системным предупреждением старого target SDK тестовой оболочки; исправлена только эта оболочка на34 и снимки пересняты. Рабочие приложения уже target34. Нативный test-пакет не является новым релизом клиента.

Native fixture не имеет семьи, сети и отправки сообщений: проверяет настоящий GIF decoder, изменение пикселей после удаления временного файла, остановку и запрет возобновления после потери scope. Второй сценарий проверяет разделение двух настоящих Material-панелей, доступность вкладок, закрытие и сохраняет снимки для визуального просмотра. Он не доказывает новый bubble на рабочем APK или доставку другому участнику.

После согласованной установки нового клиента: открыть уже отправленную GIF, убедиться в движении и прозрачном отображении; переключить фон/чат/анимацию; выбрать другую GIF как черновик, отменить без отправки; фото/аудио/документ выбирать только из скрепки. Новое тестовое сообщение отправляется владельцем в выбранной беседе, затем проверяется получатель и повтор без дубликата.

## Окружение: конкретная аппаратная проверка

На подключённом Samsung/API34 `pm list features` сообщил `android.hardware.wifi.rtt`; UWB в этом выводе не заявлен. Это признак поддержки Wi-Fi RTT телефоном, не доказательство доступных совместимых AP или точности в помещении. [Android Wi-Fi RTT](https://developer.android.com/develop/connectivity/wifi/wifi-rtt) требует совместимых ответчиков; для позиции через несколько дальностей нужны известные координаты AP. [Ranging API](https://developer.android.com/develop/connectivity/ranging) с Bluetooth Channel Sounding относится к поддерживаемым новым платформам/peer и не добавляет эту возможность любому Bluetooth-скану Android11/14. Обычный RSSI не превращаем в достоверные метры или точку карты.

Запрос состава групп и раздельного статуса «устройство на связи / участник открыл именно эту беседу» сохранён отдельно. Existing socket presence/read receipt не подменяет новый scoped foreground heartbeat с TTL. Локальное окружение обоих приложений и семейный удалённый доступ также отдельный этап с явным opt-in/grant.
