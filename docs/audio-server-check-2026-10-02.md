## Поручение серверному агенту

1. Сверить фактически запущенный код с веткой feat/family-profiles GitHub. Публикация серверных правок ещё не подтверждена владельцем.
2. За один новый сеанс проверить приём audio_chunk от child-c7d50e08, verified child source, parentSockets, активную streamingSessions/listeners и parentDeviceId сокета. Сверить идентичность слушателя между HTTP start и WebSocket register_parent.
3. Найти точную точку отказа: пакет не принят; отвергнут источник; нет родительского mapping/listener; пакет отправлен в другой/закрытый socket. Не отключать проверку AUDIO_LISTENING, не подменять адресата единственным ребёнком, не рассылать звук всем родителям.
4. После исправления дать доказательство: тот же sequence принят сервером и отправлен именно playback-сокету папы. Полный успех требует приёма на родителе и слышимого звука, не одного HTTP 200.

Журналы телефонов локально: qa/audio-2026-10-02/parent-session.txt и child-session.txt. Реальные семейные данные и аудиозаписи для диагностики публиковать не нужно.
