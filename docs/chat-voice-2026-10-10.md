# Голосовые сообщения: запись и воспроизведение

Оба существующих composer получают третий пункт «Голосовое сообщение» только при VOICE в действующем server capabilities. Доступ к микрофону запрашивается после выбора этого пункта. MIC/AAC/M4A включается отдельной кнопкой «Начать запись»; автоматической записи или отправки нет.

Общий компонент `ChatVoiceRecording` использует монотонный таймер, предел 180000мс/10МиБ и запас для завершения контейнера; проверяет фактическую длительность завершённого M4A. Файл и указатель черновика находятся в приватной папке chat-voice, разделённой SHA-256 от полного server/family/member/device/conversation scope. Поворот/уход в фон завершают запись; готовая запись доступна при следующем открытии пункта. Погибший процесс восстанавливает только валидный завершённый контейнер; повреждённая частичная запись не выдаётся за успешную.

Потеря AudioFocus, звонок/изменение AudioManager mode, silenced microphone на API29+, ошибка рекордера, недостаток места и предел времени/размера освобождают ресурсы с понятным состоянием. При возможности сохраняется готовый черновик. Тихий перезапуск микрофона не выполняется.

Диалог позволяет прослушать с паузой/перемоткой, удалить или прикрепить запись. Прикрепление сначала создаёт durable media draft прежнего этапа, затем удаляет исходный recorder draft; сообщение отправляется обычной кнопкой composer. При ошибке копирования оригинал остаётся. Готовое вложение можно прослушать нажатием его подписи. Входящий VOICE показывает длительность и открывает встроенный проигрыватель после приватного скачивания и проверки SHA-256. Проигрывание начинается только по нажатию; фон закрывает проигрыватель, AudioFocus не восстанавливает звук после звонка сам.

Сервер использует прежний закрытый attachments API, durationMs и VOICE metadata. Фактическое воспроизведение и AAC проверяются на телефонах после отдельного выпуска; серверная проверка контейнера на данном этапе проверяет сигнатуру ftyp и заявленную длительность, не декодирует аудио. До транскрибации потребуется проверка декодированного аудио worker-ом.

Проверки: VoiceRecordingPolicy3/3; core Java javac against android-34; отдельные native source tests проверяют exact scope, отказ повреждённого контейнера и запрет обхода пути, не включают микрофон. Полевой порядок после согласованного server+signed upgrade: запись 10сек → preview/seek/delete; новая запись → attach/caption/send на другое устройство; поворот/уход в фон → восстановление; запрет микрофона; короткая запись; звонок; предел3мин; offline/retry/restart без дубля; смена семьи и отзыв доступа. Транскрибация — следующий отдельный этап утверждённого плана, запись не отправляется внешнему сервису.
