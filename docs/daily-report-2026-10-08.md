## Что показывает экран

Дневной отчёт — последний пригодный накопительный снимок дня в часовом поясе ребёнка. Два снимка одного дня не складываются. Сумма означает время приложений в полученном снимке, а не подтверждённое непрерывное экранное время. Проценты — доля приложения в этой сумме.

Кнопка выбора дня предлагает только дни реально доступных снимков и режим «Последний доступный день». Явный выбор не перескакивает на сегодня при обновлении. Если выбранная дата больше недоступна, показывается отсутствие снимка этого дня, а не отчёт за другую дату. Дата и часовой пояс ребёнка видимы; время сбора показывается с датой по часовому поясу родителя. Если legacy-снимок не содержит времени сбора, конец окна можно использовать для выбора порядка, но нельзя выдавать его за известное время сбора.

Источники ограничены последними 80 передачами статуса и до 16 пригодных дней, сохранённых в памяти этого просмотра. Это не полный серверный архив дней. Таблицы app_usage_days существуют, но их наличие не означает работающие сбор и API дневного архива. Этот этап не создаёт фиктивный календарь с пустыми днями.

Для прошлой даты последнее замеченное приложение и общий поток событий текущего телефона скрываются: они не относятся к выбранному дню. Если дневного снимка нет, последние известные приложения могут показываться отдельно как недневные данные, без выдуманного дневного итога.

## Пустые данные, доступ и сбои

Пустая Map, available=false, отсутствующий список и список без положительного времени не считаются доказанным нулевым использованием. Детский collector сам отбрасывает пустые снимки; для достоверного нулевого дня нужна отдельная доработка его семантики. Нулевой расход не подставляется вместо неизвестности.

Явный usagePermissionGranted=false или ошибка системного доступа к статистике очищает сохранённый отчёт, включая старые снимки. available=false без такого признака означает неудачную/отсутствующую коллекцию и само по себе не доказывает отзыв разрешения. Серверный запрет APP_USAGE отличается от системного разрешения Android. Ошибка сети сохраняет уже показанный снимок с предупреждением, не делает его свежим.

Контекст состоит из сервера, семьи, взрослого, собственного телефона и выбранного телефона ребёнка. Смена любого компонента очищает кэш; запоздалые ответы, ошибки и обновление имени не должны попасть в новый контекст. Выбор даты сохраняется при повороте только в том же контексте. Сетевые запросы закреплены за исходным взрослым также при восстановлении авторизации; отмена coroutine не превращается в искусственный HTTP404.

## Проверка данных и серверная граница

Чистая UsageDailyReportPolicy проверяет целочисленные времена, пригодный часовой пояс, границу локального дня, окна до 26 часов с учётом DST, будущее время с допуском 60 секунд и безопасные длительности приложений. Время одного приложения не может превышать окно снимка. Последний снимок выбирается по времени сбора, затем концу окна, затем текущему источнику при полном совпадении. Непригодный новый снимок не заменяет хороший старый.

Найдена отсутствовавшая проверка адресата у GET device/status и history. DeviceStatusReadService должен проверять активную привязку и текущее право чтения. Собственные данные доступны самому телефону; удалённая активность ребёнка требует взрослого в той же семье с APP_USAGE. Новый purpose=app_usage возвращает 403 при запрете. Удаление purpose не даёт обхода: общий статус для допустимой семейной/старой связи сохраняет базовую телеметрию, но очищает поля приложений без права APP_USAGE. Чужой адресат недоступен. Семья и actorMemberId нового клиента должны совпасть с актуальной привязкой.
