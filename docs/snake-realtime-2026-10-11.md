# Совместная Змейка: серверный контракт

Этот документ описывает реализованный серверный срез. Текущие статусы и шаг
продолжения находятся только в `TODO.md`, ID `CW-NEW/TOGETHER-GAMES10.10`.

## Партия и авторизация

Существующий HTTP API семейных игр принимает `type: SNAKE_COOP`. Приглашение
адресуется каноническому участнику той же семьи; принятие вторым участником
переводит его в `SETUP`. Начальное поле 20×36, две змейки, общий счёт, сложность
`NORMAL`. Seed signed64 генерируется сервером и не меняется при повторе приглашения.
Старые крестики-нолики и Морской бой сохраняют прежние правила и маршруты.

Realtime использует отдельный Socket.IO namespace `/family-games` на обычном
`/socket.io/` transport path. Требуется действующий токен даже если основной
namespace допускает legacy-клиентов. Нельзя отправлять сюда мониторинговые
события: обработчики звука/фото и их реестры остаются в прежнем namespace.
Применяется существующий формат токена ChildWatch, не новый механизм входа.
Токен и семейный доступ перепроверяются на каждой команде; активный поток
перепроверяется раз в 250 мс. Отзыв/смена привязки убирают соединение до
следующего снимка. Идентичность игрока выводится из авторизации, а не из команды.

В `/capabilities` возвращается `SNAKE_COOP` и descriptor `realtime`:
protocolVersion1, namespace, countdownMs2000, leaseMs12000, inputWindowTicks3.
Старый HTTP бюджет 90 запросов/мин не расходуется игровыми направлениями.

## События

Все запросы используют Socket.IO acknowledgement с `success` и либо состоянием,
либо `code`. Действия клиента ограничены 20 запросами/сек и одним ожидающим
серверным обработчиком на соединение; payload не более 2048 символов JSON.

| Событие | Поля | Результат |
|---|---|---|
| `snake:join` | `gameId`, `familyId`, `actorMemberId` | Полный снимок, `player` 0(host)/1(guest) |
| `snake:command` READY | `gameId`, `epoch`, `action: READY` | Готовность игрока; оба готовы → отсчёт |
| `snake:command` INPUT | общие поля, `sequence`, `targetTick`, `direction` | Подтверждение принятия и `replayed` |
| `snake:command` PING | общие поля, `action: PING` | Снимок и продление foreground lease |
| `snake:command` PAUSE | общие поля, `action: PAUSE` | Общая пауза и новая эпоха |
| `snake:leave` | `{}` | Выход из потока и общая пауза |
| `snake:state` | от сервера | Полный снимок либо закрывающий `code` |

Направления: `UP`, `RIGHT`, `DOWN`, `LEFT`. `sequence` начинается с1 в каждой
эпохе и растёт на1 отдельно у каждого игрока. `targetTick` — целое безопасное
JSON-число от текущего тика+1 до+3. Не более двух ожидающих поворотов, на разных
возрастающих тиках; прямой разворот и повтор направления отклоняются. Эти
ограничения одинаковы для обоих участников. Сервер принимает направление,
сам рассчитывает движение, рост, еду, столкновения и результат партии.

Повтор последних32 принятых sequence с тем же телом получает `replayed: true`;
другое тело получает `SNAKE_SEQUENCE_REUSED`. Уже забытый sequence не исполняется
снова. Старый epoch отклоняется, даже если команда ещё не была подтверждена.
Realtime-направления нельзя хранить в долговременном HTTP outbox и отправлять
после восстановления новой эпохи.

## Полный снимок

`protocolVersion`, `gameId`, `epoch`, `revision`, `phase`, `reason`, `ready[2]`,
`connected[2]`, `countdownMs`, `snake`.

`phase`: `PAUSED`, `COUNTDOWN`, `PLAYING`, `FINISHED`. `revision` возрастает внутри
эпохи; разные эпохи сравнивать по принадлежности текущему подключению, не по
лексикографическому порядку UUID. `snake` содержит `columns`, `rows`, `tick`
(десятичная строка), `score`, `state`, `difficulty`, `tickMs`, `food{x,y}` и
`players[{body:[cell], direction}]`. Cell = y×20+x; первый сегмент — голова.
`state` — состояние правил, `phase` — состояние сетевой партии: перед стартом
правила могут быть READY, хотя партия уже в COUNTDOWN.

Клиент использует snapshot для отображения. Интерполяция между принятыми
положениями допустима; вычислять будущие клетки/столкновения локально нельзя.
HTTP `game.snake` — сохранённый checkpoint, а не realtime snapshot: он может
отставать до двух секунд и восстановлен в безопасном paused состоянии.

## Пауза, восстановление, хранение

Каждый игрок поддерживает foreground PING не реже одного раза в5сек. При уходе
в фон отправляются PAUSE/leave; настоящий disconnect останавливает игру сразу,
молчание без disconnect — после12сек. Пауза очищает ожидающие направления,
sequence/ready и меняет epoch. Замена соединения того же игрока снимает прежнее;
запоздавший disconnect прежнего соединения не удаляет новое.

Для возобновления нужны новый snapshot и READY обоих, затем отсчёт2сек. Повтор
READY безопасен. Время обрыва не проигрывается. Отставание серверного таймера
больше500мс приводит к `SERVER_DELAY` и паузе вместо ускоренного догоняния.
Обычные ходы выполняются по monotonic clock и текущему tickMs, без зависимости
от HTTP poll или часов телефона.

Таблица `family_snake_sessions` создаётся добавочно; старые схемы и Room не
меняются. Полный integer snapshot сохраняется примерно раз в2сек и обязательно
при паузе, готовности и завершении. Отказ записи оставляет checkpoint pending;
следующий pulse повторяет его, включая завершённую партию. После аварийного
завершения процесса допустим откат к последнему checkpoint в пределах двух
секунд; возобновление всегда на паузе с новой эпохой, без прежних соединений
и очереди команд. Числа signed64 хранятся десятичными строками; BigInt никогда
не сериализуется через JSON Number. Таблица `family_games` также обновляется
checkpoint, но закрытые через RESIGN/expiry партии не воскрешаются.

## Граница развёртывания

Движок рассчитан на **один Node-процесс, один PM2 fork instance**. Кластер и
несколько процессов над одной SQLite требуют отдельного ownership/lease
механизма; включать realtime в такой конфигурации нельзя. Перед будущей
выкладкой проверить фактическую конфигурацию VPS и сделать резервную копию базы.
Необходимый серверный delta: `index.js`, `routes/family-games.js`,
`services/FamilyGameService.js`, новые `services/SnakeRules.js`,
`services/SnakeSessionService.js`, `services/SnakeSocketService.js`.
Сервер выпускается до клиентов с семейной Змейкой. Этот этап ничего не публикует.
