# Семейные игры ChildWatch

Владелец выбрал начало разработки игр 11.10.2026. Полноценное радиоокружение отложено; его замысел сохранён отдельно. Первый сценарий: крестики-нолики между двумя участниками одной семьи, с явным принятием приглашения. Взрослый и ребёнок равноправны как игроки. Доступ к игре не даёт доступа к мониторингу.

## Правила и поведение

Инициатор играет X, приглашённый — O. До принятия ходы недоступны. Затем X начинает, игроки ходят по очереди. Победитель определяется по восьми линиям; заполнение поля без победы означает ничью. Из активной партии можно выйти с признанием победы другого участника. Ожидание приглашения можно отменить или отклонить. Ответы не отправляются автоматически от имени ребёнка.

Приглашение действует 15 минут; принятая партия — 24 часа с момента принятия. Потеря соединения сама по себе не означает отказ или проигрыш. После возвращения клиент загружает сохранённое поле. Протокол отличает окончание игры от неизвестного сетевого состояния.

Первый выпуск не требует голосовой связи, камеры, микрофона или радиосканирования. Общие рейтинги, публичные соперники, реклама и покупки не входят в сценарий. Повторную партию пока оформлять новым приглашением; будущую кнопку реванша делать с новым согласованием второго игрока.

## Серверный протокол v1

Все маршруты находятся под `/api/family-games`, существующая JWT-аутентификация обязательна. Query содержит `familyId` и `actorMemberId`. Сервер сверяет участника с подтверждённой привязкой устройства, заново проверяя её при каждом чтении и изменении. Игру читают только два её участника. Другой член семьи и другая семья по известному gameId получают 404. Устройство другого участника семьи не может представлять приглашённого по одному переданному ID.

| Маршрут | Результат |
|---|---|
| GET `/capabilities` | `protocolVersion: 1`, `games: [TIC_TAC_TOE]`, сроки |
| GET `/` | До 50 своих последних партий/приглашений |
| POST `/` | Создать приглашение: `gameId` UUID, `type: TIC_TAC_TOE`, `targetMemberId` |
| GET `/:id` | Актуальное поле и версия, свои X/O, участники, результат, сроки |
| POST `/:id/actions` | `actionId` UUID, `version`, `action`; у MOVE ещё `cell` 0..8 |

Действия: ACCEPT, DECLINE, CANCEL, MOVE, RESIGN. Состояния: INVITED, PLAYING, WON, DRAW, DECLINED, CANCELLED, RESIGNED, EXPIRED. В INVITED поле пустое и nextMark=null. Каждое принятое действие увеличивает version. Конфликт версии — 409; клиент получает новый снимок и не переносит автоматически старый ход на новую клетку.

При повторе отправки неизменные gameId/actionId сохраняются. Повтор команды от того же участника с тем же содержимым возвращает `replayed: true` и **текущее** состояние, не откатывая экран к старому полю. Повторное использование actionId с другим содержимым отвергается. SQLite-транзакция объединяет изменение поля и журнал команды: при сбое записи не сохраняется половина действия. Два телефона одного участника имеют одинаковую игровую роль; их одновременные ходы разрешаются версией.

Новые серверные таблицы: `family_games` и `family_game_actions`; создаются при первом обращении к игровому сервису. Существующие таблицы/данные/Room не меняются. Максимум пять открытых приглашений, затрагивающих одну выбранную пару; списки ограничены. Все ответы no-store. Опрос клиента предполагать только при открытом игровом экране, раз в три секунды; немедленная загрузка при возврате и после действия. Возможность клиента включать только после успешного capabilities, без ложной кнопки на старом сервере.

## Доказательства текущего этапа

`node --check` сервиса, маршрутов и index — PASS. `node --test __tests__/family-games.node.cjs` — **10/10 PASS**, без пропусков, 564,8794 мс. Настоящие SQLite-запросы и production transaction queue; семейные привязки — управляемая fixture, HTTP использует тестовую аутентификацию. Это не проверка JWT и развёрнутого VPS.

Проверены принятие, отказ, отмена, восемь линий победы X, победа O, ничья, сдача, неверная/занятая клетка, очередь ходов, одновременные команды, повтор после новых ходов, конфликт версий/nonce, откат при ошибке журнала, сроки/лимит приглашений, недоступный участник/отзыв/смена привязки, приватность маршрутов. Отдельная база в `.runtime/game-tests` закрывается и открывается заново: поле и дедупликация сохраняются. Рабочая база, телефоны и сервер не затрагивались.
