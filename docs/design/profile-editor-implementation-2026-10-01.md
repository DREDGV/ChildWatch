# Редактор своего профиля — 01.10.2026

## Объём

Свой участник семьи в ParentMonitor и ChildDevice: вход из главного окна и из раздела семьи в настройках. Редакторы сохранённых подключений и других участников не заменены; контакты/данные и значок карты остаются доступны прежними действиями.

## Решение

- Общий `FamilyProfileEditor`: предпросмотр 96dp, имя в семье, галерея, 9 первых пресетов и раскрытие всех 25; закреплённые действия под прокручиваемым содержимым.
- `ProfileAvatarChoice`: изображение 52dp, отдельное круглое кольцо 68dp и галочка. Остальные варианты сохраняют размер и яркость; accessibility checked.
- `ProfilePhotoCropDialog`: перемещение, pinch/ползунок масштаба, поворот, круговой предпросмотр. Экспорт видимого квадратного кадра в JPEG 512×512; ориентация EXIF учитывается, исходное фото не изменяется. Чтение и запись вне UI-потока; декодирование ограничено выборкой до 1600px по большей стороне.
- Масштаб и поворот имеют отдельные контролы; перемещение также доступно через accessibility actions. Отмена кадрирования сохраняет предыдущий выбор.
- Новый файл очищается при смене выбора/закрытии редактора; удаляются только созданные cropper файлы в его каталоге кеша.
- Пресеты и фото — черновик. Загрузка выполняется по «Сохранить профиль», затем публикация имени и аватара, затем локальное обновление. При отказе загрузки/публикации локальная запись не заменяется, редактор остаётся с выбранными изменениями для повторения.
- Повторная попытка публикации использует уже загруженный файл, пока выбран тот же кадр. Прежний серверный файл удаляется только после подтверждённой публикации.
- Заблокированы повторные сохранения; видимый статус и сообщение об ошибке. Выход с изменениями требует подтверждения, включая отдельный callback возврата Android 13+. Диалоги закрываются при уничтожении Activity.
- Выбор фото привязан к конкретному экрану; отмена системной галереи не оставляет редактор заблокированным. Регистрация launcher происходит до STARTED.
- Асинхронный аватар сбрасывается перед новым bind: прежнее фото не должно перекрывать выбранный пресет/кадр.
- OwnProfileEditor обоих клиентов сохраняет собственного участника; контекст телефона/семьи/сервера проверяется перед сохранением. ParentFamilyDirectoryRepository не подменяет отсутствующую выбранную семью первой попавшейся membership.

## Доказательства и ограничения

Статически прочитаны пути выбора → кадр → загрузка → публикация → локальная запись → очистка; XML двух настроек читается, ID уникальны (50/38), все новые общие ресурсы объявлены. Kotlin/Java не компилировались, тесты и сборки не запускались.

Просмотрен **браузерный макет**, а не Android: 390×844, 360×740 с шрифтом 130%; ровные аватары, footer доступен, длинный текст кнопки переносится. `profile-editor-preview.html`, `profile-editor-preview.jpg`. Реальная Android-компоновка, жесты кадрирования, EXIF, галерея и обмен фото между телефонами ещё не подтверждены.

Операции сервера и локального хранилища не являются общей транзакцией; таймаут после отправки не доказывает откат на сервере. Интерфейс говорит «Не удалось подтвердить сохранение». Неподтверждённые новые серверные файлы не удаляются автоматически, чтобы не удалить фото, которое сервер уже принял при потере ответа.

Черновик редактора пока не восстанавливается после пересоздания Activity: сохраняемый профиль остаётся цел, но повторный вход начинается с сохранённых значений. Этот пункт записан открытым в CW-04.
