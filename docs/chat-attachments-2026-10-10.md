# Вложения chat v2: контракт и проверка

Фото и файлы используют существующую беседу, текущего отправителя и прежний clientMessageId. Порядок: приватный локальный черновик → идемпотентная загрузка → вложение READY → транзакция сообщения/ссылки → обычный outbox. Повтор загрузки с другим содержимым отклоняется; повтор отправки возвращает одно сообщение.

## Сервер

`GET /api/chat/v2/capabilities`; `POST /api/chat/v2/conversations/:id/attachments` (multipart file, attachmentType, clientUploadId, optional durationMs); приватные GET `/:attachmentId/content` и DELETE `/:attachmentId` под тем же маршрутом беседы. Доступ проверяется по действующему членству, устройству, беседе и видимости сообщения. Черновик доступен только отправителю. Удаление для меня не удаляет общий файл; удаление для всех закрывает доступ.

Файл ≤25 МиБ, изображение/GIF ≤10 МиБ. Изображения проверяются по сигнатуре; произвольные файлы отдаются как attachment/application/octet-stream. SHA-256 проверяется клиентом после скачивания. Имена файлов не определяют путь хранения. Каталог `server/private-data/chat-attachments` должен оставаться вне nginx/static root; CHAT_ATTACHMENT_ROOT при переопределении также обязан быть приватным. Обработка временных файлов и удалённых объектов запускается каждые пять минут, ограничена 100 строками и 100 элементами каждого каталога за проход; итератор продолжается в следующем проходе.

DTO сохраняет совместимость старого текстового клиента: вложение без подписи получает служебную непустую строку и mediaFallback=true; новый клиент показывает медиа без этой строки. Подпись пользователя сохраняется. GIF на этом этапе имеет статический предпросмотр, анимация — следующий согласованный этап.

## Клиенты и базы

Обе Room базы повышены 12→13. Добавлена собственная зарегистрированная миграция, shipped миграции не менялись. Новые поля сообщения и таблицы черновиков/capabilities экспортированы в schemas/13.json. Черновики привязаны к server/family/member/device/conversation, содержат приватную копию и контрольную сумму; после рестарта повторяется тот же ID. Отправленные состояния ENQUEUED/SENT не возвращаются в composer.

Оба экрана используют существующие composer/bubbles: выбор фото или оригинального файла, предварительный просмотр, прогресс, отмену, повтор и приватное скачивание/открытие/сохранение. Функция скрыта на сервере без capabilities. Изменение контекста не переносит вложение в другую семью. Новая Room миграция и rendering имеют Android-тесты, выполняемые только после отдельного согласованного выпуска.

## Порядок разрешённого выпуска

Сначала сервер: database/DatabaseManager.js, services/ChatConversationService.js, services/ChatAttachmentStore.js, routes/chat-v2.js, routes/chat-attachments.js. Сохранить базу и приватный каталог, проверить capabilities/auth/отзыв/идемпотентность. Затем подписанные клиенты поверх существующих баз без удаления данных. Полевой smoke: фото и файл в личной/групповой беседе, отключение сети/повтор без дубликата, рестарт с черновиком, сохранение файла, удаление для меня/всех, крупный шрифт и отзыв доступа. Изменения карты предыдущего этапа также требуют своего серверного набора из отчёта карты.
