## Пользовательский сценарий

Одна кнопка «Игры» на главной → полноценный каталог трёх игр → отдельный
экран правил и режимов → большое игровое поле. Возврат, пауза и сохранение
прогресса доступны каждой игре. Панели не перекрывают активное поле.
Режим показывается как доступный только после появления работающего контура.

Каталог использует собственные масштабируемые иллюстрации игровых сцен,
существующие поверхности/шрифт приложения. Поля — морской фон, мятный игрок,
коралловые цели, различимые формы. Крупный шрифт допускает прокрутку экрана
правил и настроек, кнопки не меньше48dp. Отдельный тестовый пакет проверяет
отрисовку без замены рабочих приложений и доступа к семейным данным.

## Реализованный локальный срез

- Змейка: три темпа, свайпы и включаемые кнопки, яблоки/рекорды отдельно
  по сложности, пауза/фон/сохранение; разные новые партии с явным seed.
- Правила Змейки: фиксированный шаг; максимум два поворота в очереди,
  запрещён немедленный разворот; детерминированная еда; проверяемый
  целочисленный снимок; восстановление активной партии только на паузе.
- COOP правила Змейки: общее поле/счёт, одновременно оцениваются оба игрока,
  движение в освобождающийся хвост допускается только без его роста;
  встреча голов/обмен местами — столкновение. Это правила, не сетевой режим.
- Отрисовка Змейки не вычисляет игровые позиции. После паузы/новой партии
  история отображения синхронизируется; несколько шагов за задержанный кадр
  не соединяются выдуманным диагональным движением.
- Арканоид: шесть разных полей; скорость растёт между уровнями, очки/жизни
  сохраняются. Следующий уровень запускается явным действием, финальная
  победа отличается от пройденного уровня. Snapshot v3 принимает прежний v2.
- Вторая платформа Арканоида пока существует только в правилах; одиночный
  интерфейс не выдаёт это за сетевое совместное прохождение.
- Морской бой: сдвиг корабля с частичным перекрытием своего прежнего
  положения, раздельное восстановление расстановки/партии; бот продолжает
  известную ось попаданий по публичным наблюдениям, без скрытых кораблей.

## Семейный realtime: контракт следующей реализации

Змейка и Арканоид требуют другого контура, чем пошаговые выстрелы:
периодический HTTP-опрос ходов не должен определять скорость их симуляции.

1. Приглашение/принятие и два канонических участника одной семьи. Игрок —
   собственный профиль, а не выбранный на карте ребёнок. Сервер проверяет
   доступ при подключении и каждом действии; отзыв доступа закрывает поток.
2. Сервер владеет фиксированным тиком, едой/столкновениями/счётом. Клиент
   передаёт направление Змейки либо ограниченную позицию платформы,
   `gameId/member/epoch/sequence/targetTick`; не присылает итоговую победу.
3. Повтор sequence подтверждается один раз; тот же sequence с другим телом
   отклоняется. Ограничены очередь, допустимое опережение и давность команды.
   Одинаковые правила задержки применяются к обоим участникам.
4. Поток отправляет возрастающую ревизию/тик и периодические полные снимки.
   Положение интерполируется для показа, не меняя authoritative collisions.
   Старый снимок/команда другой партии или эпохи не применяется.
5. Потеря связи либо уход игрока в фон ставит кооператив на общую паузу.
   Возврат: снимок → новая эпоха → готовность обоих → отсчёт. Не проигрывать
   автоматически и не исполнять накопившееся за отключение время ускоренно.
6. Сервер сохраняет снимки партиями, не пишет SQLite на каждый кадр;
   перезапуск восстанавливает партию на паузе. Детерминизм Java/Node
   проверяется одинаковыми маршрутами команд и эталонными снимками.
   Для SplitMix64 нужен unsigned64 BigInt, не JS Number.
7. Приёмка: два настоящих клиента, смена фона, короткий отказ до60сек,
   потеря подтверждения, повтор команды, перезапуск процесса и сервера,
   смена семьи/отзыв доступа. Локальный fixture не закрывает работу VPS.
