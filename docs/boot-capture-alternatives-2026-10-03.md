# Альтернативы восстановлению микрофона через device owner

Исследование 03.10.2026 по выбору владельца. Без очистки телефона, удаления аккаунтов и смены общего управления. Очередь/текущий этап: TODO.md, CW-01/FIELD-REPEAT. Это оценка вариантов, не реализованное восстановление.

| Механизм | Что подтверждено | Ограничение для нашего сценария |
|---|---|---|
| Выбранный пользователем VoiceInteractionService | Android перечисляет его в исключениях while-in-use; выбранную голосовую службу система поддерживает запущенной | Нужна реальная функция ассистента и явный выбор пользователя. Заменяет нынешнего ассистента телефона. Роль ASSISTANT сама по себе/обычная Activity не доказывает право захвата. Reboot и camera/mic ещё не проверены для ChildWatch |
| Нажатие уведомления/виджета ребёнком | Официальное основание запуска службы с доступом к чувствительным ресурсам | Требует одного действия ребёнка; не удовлетворяет полной автоматизации. Можно упростить восстановление без настроек/перезапуска мониторинга |
| FCM high priority, WorkManager, boot receiver, отключение battery optimization | Могут поддержать доставку команд/работу служб | Исключение для запуска FGS не равно исключению для microphone/camera while-in-use. Самостоятельно не исправляют пойманный запрет |
| CompanionDeviceManager | Допускает определённые фоновые службы для реально сопряжённых устройств | Не универсальное разрешение на microphone/camera; родительский телефон через интернет не становится локальным companion автоматически |
| SYSTEM_ALERT_WINDOW | При условиях ОС допускает некоторые фоновые запуски/видимый overlay | Само разрешение не входит в подтверждённый перечень while-in-use исключений. Не обещать микрофон по одной галочке, не открывать скрытый/прозрачный экран ради обхода |
| Telecom/семейный вызов | Системный путь для настоящего звонка с UI и действиями ответа/отклонения | Другой пользовательский сценарий, не доказательство удалённой прослушки без ответа; не подменять прослушку фиктивным звонком |

## Ранее рассмотренный вариант ассистента — не выбран

Изолированный прототип **настоящего семейного голосового помощника**: действия «позови маму/папу», «забери меня» или явный запуск семейного действия; системный выбор ассистента, проверка VoiceInteractionService.isActiveService, отдельные CAMERA/RECORD_AUDIO permissions, видимые индикаторы использования и остановка. Не получать роль только формальным объявлением службы ради доступа к сенсорам.

Сначала чистый эмулятор **без device owner**, чтобы результат нельзя было объяснить прежним DPC-исключением. После reboot без открытия ChildWatch проверить system binding, actual FGS eligibility reason и микрофон/камеру. Сохранить snapshot до instrumentation, поскольку тестовый runner может влиять на привилегии. Переход на реальный телефон только после оценки результата и отдельного явного согласия на смену выбранного ассистента: это влияет на существующие функции телефона. До первого разблокирования остаётся отдельное ограничение зашифрованной сессии.

Это гипотеза для проверки, не выбранная архитектура и не обещание всех функций. Код ассистента и смена роли пока не выполнялись. Device-owner реализация остаётся сохранённым предыдущим экспериментом; не применять её к аккаунтам пользователя.

## Пересмотр 04.10: обычное восстановление и настоящий детский Home

Восстановление разделить на два уровня: (а) monitoring intent, user unlock, сеть/регистрация/чат/координаты/доставка команд; (б) отдельные действительные разрешения и platform eligibility для camera/microphone. Живой socket или isForeground не означает работающий захват. Не смешивать успешную доставку команды с появлением первого пакета/снимка. Для новых запусков аудио сохранять контекст/срок действительности, а не бесконечно оживлять старый запрос после reboot.

Новый кандидат для исследования — полноценный детский домашний экран (ROLE_HOME), выбранный пользователем через системный диалог. Это **не** привилегированное mic/camera исключение. Основание запуска — настоящий видимый Home Activity: Android допускает запуск чувствительной FGS из видимой Activity и продолжение после её ухода в фон. Когда ОС показывает выбранный Home после обычной разблокировки/перехода домой, приложение может восстановить desired monitoring и подготовить службы. Точную последовательность boot/unlock/home и сохранение допуска камеры/микрофона на OEM пока не проверяли.

Такой режим должен быть полезным домашним экраном: доступ к установленным приложениям, звонку родителю, SOS, «Забери меня»; не прозрачным/мгновенно исчезающим экраном для обхода ограничений. Одноразовый выбор изменяет текущий launcher, поэтому это предложение требует выбора владельца до применения на телефоне. Аккаунты и установленные приложения не удаляются; прежний домашний экран должен оставаться доступным для возврата. Не запускать непрерывную запись ради поддержания доступа.

Границы: до первого разблокирования остаётся защищённое хранилище; запуск самого Home/службы не гарантирует захват. Если ребёнок не разблокирует телефон и Home не становится видимым, этот способ не удовлетворяет полностью автономной прослушке сразу после boot. Уничтожение процесса/службы, конкурирующий звонок и ограничения OEM требуют отдельных проверок.

Следующий предлагаемый эксперимент: минимальный, но настоящий Home prototype в отдельном тестовом окружении **без device owner и без выбранного VoiceInteractionService**. Boot → обычная разблокировка → ОС показывает Home (без ручного открытия ChildWatch) → службы создаются из видимого Home → перейти в другое приложение/заблокировать экран → независимый запрос mic/photo, реальный результат, provenance допуска до instrumentation. Если Home не показывается автоматически или доступ не сохраняется, гипотеза отвергается. Код и default-home роль пока не изменены.

Источники: [ROLE_HOME и согласие пользователя](https://developer.android.com/reference/android/app/role/RoleManager), [видимая Activity и продолжение доступа FGS](https://developer.android.com/training/permissions/requesting), [Direct Boot](https://developer.android.com/privacy-and-security/direct-boot). Это вывод из документов, а не результат теста нового механизма.

Действительно отрисованный Home → фон/погашенный дисплей: unsilenced AudioRecord и JPEG, reason TOP, без DPC/assistant. [Отчёт и границы](boot-capture-home-probe-2026-10-04.md); физические телефоны/серверная доставка не проверены. Предыдущая формулировка про отсутствие теста относится к исходному исследованию выше.
