# CW-07: локальный просмотр и повтор подтверждения

Причина этапа: пользователь видит сообщения, но неудачный HTTP receipt оставлял их непрочитанными локально; поздняя синхронизация дополнительно могла возвращать старую отметку. Предыдущая merge policy уже проверена десятью сценариями. Этот этап разделяет просмотр на своём телефоне и подтверждённое сервером прочтение.

Изменены оба ChatV2Repository, ChatConversationV2Activity, ChatOutboxV2Dao/ChatMessageV2Dao; добавлены shared ChatV2ReadReceiptPolicy/test и chat_read_receipt_texts.xml обоих клиентов. Room entity/schema/version12 не менялись.

Локальная транзакция записывает viewed watermark, is_read входящих сообщений и scoped READ_PENDING в существующий outbox. Повтор одной границы использует тот же ключ. Она не меняет серверный delivery_state/read_at и чужие receipts. Очередь отделена от отправки сообщений, проверяет сервер/семью/самого участника/устройство и принадлежность беседы. HTTP ack проверяется до/после ожидания; состояние READ_SENT появляется только после подтверждения нужной границы нужным серверным участником. Отказ/401/403 остаются pending с backoff. Lease и token предотвращают параллельное завершение чужой отправки; отмена/перезапуск оставляют строку для повторного захвата после истечения lease. Повтор вызывают refresh/flush существующей синхронизации.

Экран фиксирует локальную границу после применения списка и определения видимого сообщения, только в RESUMED и возле конца списка. Сохранённая offline-история участвует в том же пути. Сам факт получения страницы/пакета больше не отмечает всю страницу прочитанной. UI показывает ожидание серверного подтверждения отдельно.

Новая policy имеет3 адресных теста: локально полностью просмотренная история/частичная, смена actor/server/family/device и неверный member в позднем ack, отсутствие канонического контекста. Эти тесты не доказывают конкуренцию Room/жизненный цикл Android или доставку серверу. Открытый сценарий: offline cache→badge исчезает локально→перезапуск процесса→сеть→серверный ack; также401/403, смена контекста во время запроса, параллельный flush, прокрутка вверх. Новый server snapshot при pending read может временно сохранить консервативный unread до ack; точный счётчик не реконструируется из seq-read, поскольку последовательности содержат собственные сообщения.
