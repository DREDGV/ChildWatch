# Рабочий процесс ChildWatch

TODO → один пользовательский результат → затронутый код → соразмерная разрешённая проверка → запись результата.
Очередь и ограничения находятся только в TODO; навыки не хранят текущие версии, серийники и статусы.

После задачи/этапа агент даёт одну следующую рекомендацию, при необходимости одну альтернативу: ожидаемый результат и причина из свежих находок. Новый дефект сразу попадает в TODO; идея улучшения записывается как предложение до выбора владельца. Рекомендация не расширяет разрешённый объём работы.

## Контракт этапа и продолжение

Адаптация [Learn Harness Engineering](https://github.com/walkinglabs/learn-harness-engineering), 02.10.2026: инструкции, состояние, проверка, границы задачи и передача между сессиями. Подключение проектных инструкций через AGENTS.md описано в [официальной документации](https://developers.openai.com/codex/guides/agents-md).

1. **Вход:** прочитать TODO и правила; посмотреть исходное git-состояние. Найти нужный ID, сохранить ограничения владельца. Чужие изменения не считать своей работой.
2. **До правки:** добавить в этот ID короткий контракт: какой результат увидит пользователь, какие части меняем, чем подтвердим готовность. Если проверка запрещена или недоступна, заранее указать это.
3. **Работа:** один связный этап; читать подробности по необходимости. При сбое собрать конкретное свидетельство, исправить причину и повторить затронутую проверку. При повторении того же сбоя без новых данных сменить гипотезу; при внешнем блокере записать его и точное действие для продолжения.
4. **Проверка:** использовать существующие команды ниже и доказательство нужного уровня. Исходники, сборка, установка, реальный сценарий и выкладка сервера — разные результаты. Недоступную проверку не заменять предположением; статус [v] сохраняет оставшуюся runtime-проверку.
5. **Выход:** обновить тот же ID: результат, затронутые файлы, выполненные проверки/ссылки, что не доказано, следующий конкретный шаг. В следующем чате продолжать с этой записи, сверяя только факты, от которых зависит действие.

Минимальная запись в TODO (шаблон, не отдельная очередь):

```text
ID · статус · дата
Результат/границы: …
Готовность: наблюдаемый сценарий и требуемое доказательство …
Изменено: пути …
Проверено: команда/сценарий → результат; файл свидетельства …
Не проверено/ограничения: …
Продолжить: одно конкретное действие …
```

Проверки выбирать по изменению, а не запускать весь набор на каждом входе:

- Документация: `git diff --check -- AGENTS.md docs/agent-workflow.md TODO.md`, проверить ссылки и отсутствие противоречий.
- Android, когда разрешено: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-gradle-safe.ps1 :shared-core:test :app:compileDebugKotlin :parentwatch:compileDebugKotlin`; дать компиляции минимум 900 секунд, сообщать ход работы.
- Выпуск/установка, только в разрешённом объёме: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-and-install.ps1 -BuildTimeoutSeconds 900`; параметры цели и установки выбирать по поручению и release-навыку.
- Сервер: `node --check <изменённый-js-файл>` подтверждает только синтаксис; реальные права, доставка и работа развёрнутой версии требуют отдельного сценария.

Новые feature_list.json, progress.md и init.sh не нужны: их роли уже выполняют TODO, проектные инструкции и безопасные Windows-скрипты. Это изменение правил работы, а не обучение весов модели. Эффект оценивать на следующих задачах: сохранён ли контекст, совпала ли заявленная готовность с доказательствами, сколько раз владельцу пришлось повторять ограничения. Сам факт наличия документов не доказывает улучшение надёжности.

## Пересмотр общих навыков

| Навык | Применение в ChildWatch |
|---|---|
| skill-creator | Создание/изменение конкретного навыка; короткие инструкции и условные подробности. Использован для этого обновления. |
| diagnosing-bugs | Сложный воспроизводимый сбой, когда запуск проверок разрешён. При запрете тестов/сборок разрешена работа с исходниками, проверка остаётся открытой; указание владельца имеет приоритет. |
| code-review | Явная ревизия относительно коммита/ветки. Общий навык требует двух агентов и отдельного issue-tracker; не применять ради обычной мелкой правки. |
| writing-plans / executing-plans | Отдельный согласованный многоэтапный план. Не создавать подробный план, TDD, обязательные коммиты и документы для каждого изменения. |
| domain-modeling | Меняется смысл человека/устройства/семьи или принято архитектурное решение. Для обычного чтения CONTEXT не нужен. |
| tdd | Владелец просит работу сначала через тест, либо проверки разрешены и нужен регрессионный сценарий. |
| frontend-design / design-system / accessibility-review / design-critique / user-research | Подготовлены проектные готовые навыки; один основной frontend-design, остальные по задаче. Вход: DESIGN.md, DESIGN_REFERENCES.md и docs/design-bootstrap.md. Для Android проверять настоящий экран; React/CSS правила не переносить механически. |
| openai-docs | Отдельный вопрос Codex/OpenAI, не основная разработка ChildWatch. |

Глобальные и поставляемые плагинами навыки сохранены: они используются другими проектами. Проектные дополнения устраняют повторную подготовку.

## Экономия повторяющейся работы

- Искать сначала в модуле задачи; расширять поиск при пересечении границы клиента/сервера.
- Независимые чтения объединять; перед правкой читать точный участок. Русский XML/Markdown менять адресно.
- Git-состояние смотреть в начале этапа, затем дифф затронутых файлов; повторять общий осмотр при внешнем изменении.
- ADB/сервер/manifest проверять перед установкой, публикацией или живой диагностикой, а не перед каждой правкой.
- Не читать весь архив TODO, журналы и набор навыков: один ID и нужный раздел.
- Не повторять успешную проверку без изменения поведения или конкретной оставшейся неопределённости.
- Историю не считать текущим состоянием; незавершённая проверка остаётся видимой после готовности исходников.
