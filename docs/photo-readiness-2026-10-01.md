# CW-05 / CW-09 · Диагностика камеры · 01.10.2026

## Результат в исходниках

- ChildDevice `CameraDiagnostics`: свежий снимок CAMERA permission, системного sensor privacy (Android 12+), наличия основной/фронтальной камеры; диагностика не открывает камеру. Неизвестный ответ остаётся неизвестным. Последний исход фото хранится отдельно по серверу и собственному телефону, успешная загрузка заменяет старую ошибку.
- `DeviceInfoCollector` добавляет camera в существующий raw status без изменения Room. Главный экран ребёнка публикует лёгкий статус при возвращении из настроек независимо от службы GPS; обычные статусные сообщения продолжают обновлять сведения.
- `GET /api/photo/readiness/:deviceId` использует тот же CHILD/REMOTE_PHOTO gate, что команда фото; возвращает соединение явно выбранного телефона, занятость запроса и последний camera snapshot. Другого ребёнка не подставляет, при чтении статуса учитывает формы ID.
- ParentMonitor `PhotoReadinessSummary`: одно представление для диагностики и окна фото. Свежесть camera collectedAt 2 минуты с небольшим допуском часов. Нет данных, старый снимок, отказ прав семьи, нет соединения, занятость, CAMERA denied, sensor privacy и отсутствующая камера различаются. Последний переданный результат имеет собственное время и не доказывает текущую готовность.
- Главное окно: строка Фото ребёнка в уже существующей диагностике; по нажатию — подробности и путь в настройки нужного телефона. Для взрослых строка скрыта.
- Окно фото: подробности по статусу, обновление раз в 30 секунд только в видимом окне и проверка до запроса (HTTP call timeout 8 сек). Доказанный запрет объясняется до съёмки; неизвестное/старое состояние допускает попытку. При смене человека, остановке окна или позднем ответе новый запрос не должен уйти старому адресату.
- Выбранную фронтальную/основную камеру больше нельзя незаметно заменить противоположной, возвращается camera_not_available.

## Доказательства / открыто

Node syntax server/index.js, WebSocketManager.js PASS; XML обоих затронутых layout и новых strings PASS, ссылки на новые ресурсы найдены, diff whitespace check PASS. Browser-макет 360×640/130%: запрет камеры и пояснение просмотрены; contentHeight == clientHeight на основном окне. `docs/design/photo-readiness-preview.jpg`.

Android/Kotlin не компилировались, сервер не запускался/не публиковался, телефоны не проверялись: ограничение владельца на тесты/сборки сохраняется. Требуются оба клиента и сервер. Макет не является нативным доказательством. Старый сервер без readiness возвращает неизвестное состояние, а не вечную блокировку. Системный доступ к камере не гарантирует фоновой съёмки; это явно объяснено. Большой native font/landscape и инструкции OEM нужно проверить при следующем разрешённом запуске.
